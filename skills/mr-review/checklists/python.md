# Python 점검 목록

> 출처: [alibaba/open-code-review](https://github.com/alibaba/open-code-review)의 `internal/config/rules/rule_docs/python.md` (Apache License 2.0. 사본은 이 폴더의 `LICENSE-open-code-review.txt`).
> 바꾼 것: 한국어로 옮겼고, 도구 이름(`file_read`)을 "코드를 읽어"로 바꿨고, 이 플러그인의 판정 규칙에 맞춰 범주마다 기본 심각도를 덧붙였다.

**재현율보다 정확도.** 진짜 결함이라고 확신할 때만 지적하고, 주변 맥락이 불분명하면 먼저 코드를 읽어 확인한다. 헛경보는 사소한 누락보다 리뷰 신뢰를 더 깎는다. 보안·정확성 지적은 병합을 막는 쪽으로, 문체·관용구 제안은 막지 않는 쪽으로 다룬다.

각 범주의 **기본 심각도**는 출발점이다. 실제 입력에서 잘못된 결과·크래시·데이터 손상으로 이어지는 것이 확인되면 `[높음]` 으로 올린다.

## 오타 — 기본 `[낮음]`

- 변수·함수·클래스·모듈 이름의 오타. **선언한 곳에서만** 지적한다. 참조하는 곳의 철자는 선언이 정한다
- 로그·예외 메시지의 오타 중 읽기를 방해하는 것

## 죽은 코드 — 기본 `[낮음]`

- 절대 도달하지 않는 코드 (조건이 항상 거짓인 분기, `return`·`raise`·`break`·`continue` 뒤의 코드)
- 선언하고 한 번도 읽지 않는 변수·import·함수 인자
- 남겨 둘 의도가 보이지 않는 대량의 주석 처리된 코드
- `.pyi` 스텁 파일의 안 쓰는 import·변수·인자는 지적하지 않는다. 스텁은 실행하지 않는 인터페이스 선언이라 재수출 import와 주석 전용 선언이 정상이다

## 가변 기본 인자와 공유 상태 — 기본 `[중간]`

- `def f(x=[])`, `def f(x={})` 같은 가변 기본 인자. 기본값은 한 번만 만들어져 모든 호출이 공유한다. `None` 을 기본으로 두고 본문에서 만든다
- 인스턴스마다 따로 가져야 할 값을 클래스 수준 가변 속성으로 둬서 인스턴스끼리 공유되는 경우
- 요청이나 스레드를 넘어 변경되는 모듈 수준 가변 전역(리스트·딕셔너리·캐시)
- 반복 변수를 참조로 붙잡은 클로저가 모두 마지막 값을 보게 되는 경우
- 함수가 인자를 변경하지 않거나, 공유 기본값이 의도적이고 문서화된 캐시·센티널이면 지적하지 않는다

## 경계와 에지 케이스 — 기본 `[중간]`

- 비어 있을 수 있는 입력을 비어 있지 않다고 가정: 빈 `list`·`str`·`dict`·이터레이터를 처리하지 않고 `xs[0]`, `max()`/`min()`, 슬라이싱
- 인덱스·범위·슬라이스의 off-by-one과 범위 밖 접근, 특히 첫·마지막 원소
- 상위 호출이나 기본값이 정당하게 `None` 을 돌려줄 수 있는데 값이 있다고 가정하는 코드 (지적 전에 데이터 출처를 코드로 확인한다)
- 부동소수점을 `==` 로 정확히 비교. `math.isclose` 나 명시적 허용오차를 쓴다
- 정수·실수 나눗셈 가정: `//` 로 의도치 않은 절삭, 나누는 수가 0이 될 수 있는데 `ZeroDivisionError` 처리 없음
- 한 종류라고 가정한 컬렉션에 섞인 타입 (`None`·숫자·문자열 혼재)
- 키가 없을 수 있는데 `d[k]` 로 접근, 또는 키가 있다고 가정한 집합·딕셔너리 연산
- 호출부나 타입 계약이 이미 배제한 경우, 상위에서 검증돼 들어올 수 없는 입력이면 지적하지 않는다

## 예외 처리 — 기본 `[중간]`

- 맨 `except:` 는 `KeyboardInterrupt`·`SystemExit` 까지 삼킨다. 최소 `except Exception`, 가능하면 예상하는 구체적 예외를 잡는다
- 처리하려는 실패보다 넓은 `except Exception`. 보호하는 호출이 실제로 던지는 예외로 좁힌다
- 잡은 예외를 로그도 재발생도 없이 `pass` 로 버림 — 실패가 성공처럼 보이면 `[높음]`
- 다시 던질 때 원래 traceback을 잃음. `raise NewError(...) from err` 로 원인을 보존한다
- 실제로 실패할 수 있는 줄보다 훨씬 넓게 감싼 `try` 가 오류의 출처를 가림
- 외부 입력의 런타임 검증에 `assert` 사용 — `python -O` 에서 제거된다

## 식별·동등 비교 — 기본 `[중간]`

- 문자열·숫자·튜플 리터럴과 `is`/`is not` 비교. 구현별 인터닝에 기대는 것이지 값 비교가 아니다 — `==` 를 쓴다 (실제 정확성 위험)
- `True`/`False` 와 `==` 비교. `1` 이나 비어 있지 않은 컨테이너처럼 참이지만 `True` 는 아닌 값이 다르게 비교된다. 참·거짓 검사를 그대로 쓴다
- `is` 는 싱글턴·센티널 식별 비교에만 쓴다
- `None` 을 `==`/`!=` 로 비교하는 것은 문체 문제다 — `[낮음]`

## 자원 관리 — 기본 `[중간]`

- 파일·소켓·잠금·DB 연결을 `with` 없이 열어 조기 반환이나 예외 때 새는 경우
- 컨텍스트 매니저가 있는데 수동 `open()`/`close()` 로 우회
- `try` 에서 얻은 자원의 `finally` 정리가 없거나 오류 경로에서 불완전
- 자원을 필요 이상 오래 붙잡는 이터레이터·제너레이터
- 짧게 끝나는 스크립트, 바깥 `with` 나 프레임워크가 수명을 관리하는 핸들은 지적하지 않는다 (지적 전에 주변 범위를 코드로 확인한다)

## 성능 — 기본 `[낮음]`, 뜨거운 경로에서 확인되면 `[중간]`

데이터 규모와 그 코드가 자주 도는 경로인지 먼저 확인한다.

- 반복문 안에서 `+=` 로 문자열을 쌓음. 리스트에 모아 `"".join(...)` 하거나 f-string을 쓴다
- `list` 에 대한 반복적인 포함 검사. `set`·`dict` 로 O(n)을 O(1)로
- 제너레이터로 충분한데 전체 리스트를 만들어 메모리에 올림
- 반복마다 같은 값을 다시 계산 (정규식 컴파일, 뜨거운 경로의 속성 조회)
- `logging.info(f"...")` 처럼 미리 포맷한 문자열을 넘김. `logging.info("%s", value)` 로 넘겨야 레벨이 꺼졌을 때 포맷을 건너뛴다

## 동시성과 비동기 — 확인되면 `[높음]` (보호 대상)

멀티스레드·멀티프로세스·비동기로 호출된다는 근거가 있을 때만 지적한다 (호출 맥락을 먼저 확인한다).

- GIL 아래에서 CPU 작업을 `threading` 으로 병렬화. 프로세스 풀이 맞다 (전통적 CPython 기준, free-threaded 빌드 제외). I/O 작업은 스레드가 실제로 도움이 된다
- 공유 상태를 `Lock` 없이 검사한 뒤 행동(check-then-act), 원자적이라고 가정한 비원자적 복합 갱신
- `async def` 안의 블로킹 호출 (동기 I/O, `time.sleep`, `requests`, CPU 과부하) — 이벤트 루프를 멈춘다. 비동기 대응물을 쓰거나 executor에서 돌린다
- 만들고 기다리지 않은 `asyncio` 태스크. 예외가 삼켜지고 끝나기 전에 수거될 수 있다
- 스레드·태스크 사이에서 동기화 없이 공유하는 가변 상태

지역 변수(스레드마다 따로), 공유 데이터의 읽기 전용 접근, 동시 사용의 근거가 없는 코드는 지적하지 않는다.

## 보안 — 기본 `[높음]`

데이터 출처를 먼저 확인한다. 입력이 실제로 공격자가 제어할 수 있는지, 신뢰하는 상수인지 가린다.

- 신뢰할 수 없는 입력에 `eval`·`exec`·`compile` — 임의 코드 실행
- 정제하지 않은 입력으로 만든 `shell=True` 의 `subprocess`. 인자 리스트를 넘기고 셸을 피한다
- 신뢰할 수 없는 데이터에 `pickle`·`marshal`·`SafeLoader` 없는 `yaml.load` — 역직렬화가 임의 코드를 실행할 수 있다
- 파라미터 바인딩 대신 문자열 연결이나 f-string으로 만든 SQL
- 로그에 남기거나 소스에 커밋한 비밀값·토큰·비밀번호·개인정보
- 약하거나 잘못 쓴 암호 (`hashlib.md5`/`sha1` 로 비밀번호, 보안 토큰에 `random`). `secrets` 와 검증된 라이브러리를 쓴다
- 검증 없이 이어 붙인 신뢰할 수 없는 파일 경로 — 경로 탐색 공격
