# 리뷰봇 설계와 작업 맥락

기준일: 2026-10-20 KST. 이 문서는 구현된 기능과 앞으로의 합의를 구분해 보관합니다.

## 현재 단계

MMP 기존 코드를 확장한 로컬 MCP 서버입니다. 실행 검증 기준은 Node.js 24이며 최소 요구 버전은 Node.js 22.13입니다. 실제 GitLab 수신에는 별도 HTTPS 경로가 필요합니다.

MCP는 로컬 stdio 방식으로 연결하고, GitLab 웹훅은 별도 프로세스가 `127.0.0.1`에서 받습니다. 두 프로세스는 같은 비공개 데이터 디렉터리와 `reviews.sqlite3`를 공유합니다. 웹훅 수신기의 `/health`는 HTTP 상태 조회이며 MCP 연결 주소가 아닙니다. 실행 명령과 환경변수는 저장소 README를 기준으로 합니다.

웹훅 인증·프로젝트 허용 목록·이벤트 필터링·SQLite 대기열과 조회 도구에 더해 팀원 프로필 등록, Jira Cloud 조회·이력 보관, 월요일 요약, 리뷰 직전 최신화와 구조화한 리뷰 기록의 누적·재참조를 구현했습니다. 등록 인원에 고정 상한은 없으며 리뷰 준비와 주간 요약에는 팀원이 1명 이상 필요합니다. 웹훅 수신부터 코드 리뷰·댓글·작성자 Mattermost DM까지의 자동 worker도 구현했으며 기본값은 비활성입니다. 자세한 설정은 [팀 작업 맥락](TEAM-CONTEXT.md)과 [자동 리뷰 운영](AUTO-REVIEW.md)에 기록했습니다. 운영 계정 검증과 5분 API 폴링을 통한 웹훅 누락 보충은 아직 수행하지 않았습니다.

설치할 팀의 계정과 프로젝트 범위는 명시적으로 등록합니다. 특정 프로젝트를 기본값으로 선택하지 않습니다.

## 최종 역할 분담

수동 MCP 사용에서는 대화가 코드를 검토하고 판단합니다. 자동 worker를 켜면 서버가 로그인된 Claude Code CLI를 별도 프로세스로 실행해 수집 자료를 검토합니다. CLI는 임시 작업 폴더·도구 비활성·빈 MCP 구성으로 실행하며 코드나 테스트를 실행하지 않습니다. 서버가 `glab`으로 전체 diff·변경 전후 파일·MR 설명과 댓글을 읽고 최신 Jira 관점·누적 기록과 함께 전달합니다. 모델이 연결한 서비스가 이 자료를 처리하므로 설치 환경의 CLI 인증과 사용량이 적용됩니다.

선점·리뷰·게시·알림은 worker 내부에서 수행합니다. SQLite lease와 checkpoint가 재시작 상태를 보관하며 `review_worker_status`와 `review_job_retry`가 운영 조회·최종 실패 재시도를 제공합니다. 게시 댓글의 숨은 식별자는 설정한 호스트·프로젝트·MR·SHA에 고정됩니다. 게시 재시도는 자신의 기존 댓글을 먼저 확인하며 다른 내용의 댓글을 덮어쓰지 않습니다. 알림 전송 불명은 `notification_unknown`으로 멈추고 명시적인 중복 허용 없이는 재전송하지 않습니다.

자동 worker는 MCP 서버 안에서 또는 별도 `worker:serve` 프로세스로 실행할 수 있습니다. 기본 5초 확인은 로컬 SQLite 대기열 확인입니다. 앱의 예약 실행이나 GitLab 5분 API 폴링에 의존하지 않습니다. 프로세스가 꺼지면 처리하지 못하므로 상시 실행은 설치자가 구성해야 합니다. 저장된 작업은 lease 만료 후 복구하지만, 전달되지 않은 웹훅은 API 폴링으로 보충하지 않습니다.

## MMP 원본과 보완 범위

기준 소스는 [MMP 0.6.1, 커밋 943ae776026daa4ec8d230f0fb65ddd35ea8c6f2](https://github.com/kdHyeok/MMP/tree/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2)입니다. 기존 stdio MCP, Mattermost 사람·채널·템플릿 저장, 미리보기·전송 검증과 테스트 구조를 재사용합니다. 리뷰 단계·게시·알림을 분리한 원칙도 유지합니다. 원본에서 제공하는 기능과 이번 대기열에 연결된 기능은 구분합니다.

- 원본 MCP는 Mattermost 관리·전송 도구 중심입니다. 리뷰 자료·작업 상태·게시를 담당할 MCP 도구를 추가합니다. [서버](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/src/server.js)
- 원본 웹훅 등록은 Mattermost로 보내기 위한 주소 저장입니다. GitLab 이벤트를 받는 별도 수신기를 추가합니다. [웹훅과 저장](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/src/core.js#L159-L200)
- 원본 감시기는 60초마다 pending todo 첫 100개를 조회하고 최근 todo ID로 중복을 줄입니다. 추적 MR의 SHA 비교, 페이지 순회와 누락 복구를 보완합니다. [감시기](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/bin/mr-watch.mjs#L130-L164)
- 원본의 이벤트 출력·seen 저장과 워크트리 상태 파일을 작업 완료 기록으로 간주하지 않습니다. SQLite에 선점·실패·재시도와 게시·알림 결과를 각각 보관하고 게시 직전에 최신 SHA를 확인합니다. [리뷰 상태와 게시](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/bin/mr-review.mjs#L367-L456)
- 원본 사람 연결은 사용자명 중심이며 Jira 이슈·주간 맥락 저장은 없습니다. 서비스별 안정적인 계정 ID와 아래의 이슈 원본·개인별 요약 구조를 추가합니다. [사람 저장](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/src/core.js#L185-L200)
- 원본의 메시지 미리보기·형식·수신자 검증을 유지하고 전송 결과를 영속 기록합니다. 타임아웃처럼 실제 전달 여부를 확정할 수 없는 실패를 구분하여 중복 알림을 줄입니다. [전송](https://github.com/kdHyeok/MMP/blob/943ae776026daa4ec8d230f0fb65ddd35ea8c6f2/src/core.js#L539-L585)

## 리뷰 시작과 재검토

최초 추적을 시작하는 조건은 다음 세 가지입니다.

1. MR 설명에 사용자 계정이 `@멘션`됨.
2. MR 댓글에 사용자 계정이 `@멘션`됨.
3. 사용자가 MR 리뷰어로 지정됨.

담당자 지정만으로는 시작하지 않습니다. 추적을 시작한 열린 MR은 새 커밋이 올라오면 다시 검토합니다. 닫힘·머지 상태는 추적 상태에 반영합니다. 봇 자신의 댓글과 이벤트로 재검토가 반복되지 않도록 제외합니다.

웹훅은 이벤트가 생겼을 때 GitLab이 수신기로 보내는 방식입니다. 이벤트 식별자와 프로젝트 ID·MR 번호·현재 SHA를 기준으로 중복을 제거합니다. worker는 설정한 단일 GitLab 호스트와 허용 프로젝트 ID로 실제 MR 주소를 조회합니다. 웹훅에 들어 있는 URL이나 저장소 경로를 실행 대상으로 믿지 않습니다. 게시 직전에 현재 SHA·열림·비draft·활성 lease를 확인합니다. 새 커밋·닫힘·draft는 이전 리뷰의 새 댓글 게시를 막지만, 이미 게시한 댓글의 완료 알림은 복구할 수 있습니다. 5분 API 누락 확인은 이후 단계입니다.

이 저장소는 공개 수신 주소를 자동 구성하지 않습니다. 로컬 수신 테스트가 통과해도 실제 GitLab 웹훅이 도착한다고 볼 수 없으므로 설치 환경의 HTTPS 전달 경로를 별도로 확인합니다.

## 사람과 이슈를 연결하는 방법

등록할 팀원에게 안정적인 내부 식별자를 하나씩 부여합니다. 현재 등록 도구는 GitLab 숫자 사용자 ID(선택)·사용자명과 Jira `accountId`, 담당 영역·경로·검토 초점을 받습니다. Mattermost 매핑은 기존 참가자 도구에서 별도로 관리합니다. GitLab 숫자 ID가 있으면 우선 사용하고, 없으면 정확한 사용자명을 사용합니다. 서로 다른 GitLab 인스턴스의 동일 숫자 ID를 한 팀에서 함께 사용하는 구성은 아직 지원하지 않습니다. 같은 표시 이름이라는 이유로 자동 연결하지 않습니다.

작업 기록의 원본 단위는 Jira 이슈입니다. 사람별 폴더는 담당 이슈 링크와 주간 요약을 보여주는 용도로 사용합니다. 담당자가 바뀌어도 이슈 기록을 복제하거나 이동하지 않습니다.

```text
비공개 데이터 디렉터리/
  mattermost.sqlite3
  reviews.sqlite3
  team-context.sqlite3
  issues/<Jira키>/context.md
  issues/<Jira키>/review-history.md
  people/<개인식별자>/profile.md
  people/<개인식별자>/weeks/<월요일날짜>.md
  reviews/<MR URL 해시>/<SHA>.md
  reviews/<MR URL 해시>/history/<기록ID>.md
```

이 구조는 비공개 데이터 디렉터리에 구현했습니다. 실제 계정과 Jira 연결 전에는 운영용 개인별 자료를 생성하지 않습니다. 기존 Mattermost 설정은 `mattermost.sqlite3`, 수신함은 `reviews.sqlite3`, 프로필·이슈·요약은 `team-context.sqlite3`로 관리합니다. 기본 데이터 위치는 MMP의 `~/.mmp/`, 변경 설정은 `MATTERMOST_MCP_DATA_DIR`입니다. 두 프로세스가 같은 위치를 사용해야 합니다.

현재 이슈 기록은 Jira 제목·설명, 상태·담당자 변경 이력, 컴포넌트·스프린트, 원본 URL·갱신·조회 시각을 보관합니다. MR별 맥락 파일에 연결 이슈와 SHA를 함께 기록합니다. `review_context_complete`는 검토한 구현 방식·결정 이유·검증·남은 작업을 근거와 함께 비공개 누적합니다. 원문은 MR별 `history`에 한 번 저장하고 이슈별 파일에는 링크 목록만 둡니다. Jira 최신화로 이 기록을 덮어쓰지 않습니다.

리뷰를 수행한 대화 또는 자동 실행기가 기존 MR 설명·댓글·코드와 검증 출처를 근거로 내부 JSON을 작성합니다. 수동 준비 도구는 기존 MR 제목·설명을 길이 제한과 함께 반환하며 댓글은 별도 확인이 필요합니다. 자동 worker는 MR 댓글을 페이지 순회해 수집합니다. 직접 확인한 사실과 출처의 진술을 구분하고, 결정 이유를 모르면 `reason: null`, 확인되지 않은 내용은 `unknown`으로 남깁니다. 자동 실행기는 테스트를 실행하지 않으며 작성자가 보고한 결과를 직접 실행 결과로 저장하지 않습니다. 정규화한 메모리는 전체 64KiB 이내입니다. MR 양식은 바꿀 필요가 없습니다. MR에서 Jira키를 찾지 못하면 수동 `review_context_prepare`의 선택 `jira_keys` 인수로 연결할 수 있으며, 자동 worker는 제목·설명·브랜치에서 찾은 키만 연결합니다. 키가 없으면 임의 연결 없이 MR·SHA와 변경 파일로 기록합니다.

다음 준비는 같은 MR·연결 Jira키·같은 호스트와 프로젝트의 정확히 같은 변경 파일에 해당하는 이전 기록을 최신 최대 10개·100,000 JSON 문자까지 자동 참조합니다. 명시적으로 연결한 Jira키는 다른 저장소의 기록도 연결할 수 있습니다. 항목 중간을 자르지 않고 자동 응답에서 변경 경로 색인만 생략합니다. 더 필요한 자료는 `nextOffset`과 `review_history_list`로 조회합니다. 당시 SHA의 자료이므로 현재 요구·코드와 다시 대조하고 남은 작업을 자동으로 해결 처리하지 않습니다. 기록의 `reviewed`는 로컬 저장 단계이며 Jira 완료·댓글 게시·승인·머지를 의미하지 않습니다.

기존 프로젝트 문서와 MR 템플릿을 먼저 사용합니다. MR 템플릿은 초기 운영에서 그대로 유지하고, 실제 누락이 반복될 때 개선합니다. 공통 규칙을 여러 개인 파일에 복사하지 않고 원본 문서를 연결합니다.

## 갱신과 주간 요약

MCP 프로세스가 실행 중이면 매주 월요일 09:00 KST에 사람별 주간 요약을 만듭니다. 1분 간격 확인과 재시작 보충 실행을 사용합니다. 완료한 주라도 새 팀원 추가로 해당 주 요약이 없는 사람이 생기면 다음 확인 시 등록 팀원을 모두 갱신하고 보충합니다. 완료 이력의 기간은 지난 월요일 00:00부터 이번 월요일 00:00 직전까지입니다. 진행·예정은 생성 시점의 상태를 사용합니다. 가상 Jira 데이터로 분류·실패 보존·중복 방지를 검증합니다. 실제 예약 시각에 운영 Jira로 실행하는 검증은 계정 연결 후 진행합니다.

| 분류 | 기준 |
|---|---|
| 완료 | 기간 내 Jira 완료 전환. MR 머지와 테스트 확인 여부를 별도로 표시 |
| 진행 | 생성 시점에 진행 중인 이슈 |
| 예정 | 현재 스프린트에서 아직 시작하지 않은 이슈 |

스프린트 계획이 아직 없으면 미확정이라고 적습니다. 완료 시점을 확인하지 못하면 현재 완료와 완료일 미확인을 구분합니다. 완료 후 다시 열린 작업은 현재 상태와 재개 사실을 함께 남깁니다. 활동이 없으면 변경 없음으로 표시하고 새로운 업무를 추정하지 않습니다.

MR 리뷰 직전에 현재 SHA·작성자·연결 Jira·전체 변경 경로와 등록 팀원의 Jira 정보를 다시 확인합니다. 주간 요약은 최신 상태를 대신하지 않습니다. 수동 검토의 대화가 직접 읽거나 자동 worker가 코드·논의를 수집하며 외부 문서·첨부파일은 자동 수집하지 않습니다. 준비 마지막과 게시 직전에 SHA가 달라졌으면 중단합니다. 같은 SHA에서 MR 설명만 바뀐 상황을 다시 확인하는 처리는 아직 없습니다.

- 담당 변경: 현재 담당자를 갱신하고 변경 이력을 남깁니다. 이전 주간 요약은 유지합니다.
- 조회 실패: 마지막 성공 시각과 실패 범위를 남깁니다. 실패를 작업 없음으로 취급하지 않습니다.
- 삭제·권한 상실: 조회할 수 없음으로 표시합니다. 기존 기록을 조용히 삭제하지 않습니다.
- Jira 누락·연결 불명확: 완료 조건 충족 판단을 보류하고 코드에서 확인 가능한 결함과 변경 영향만 검토합니다.
- 테스트 미실행: 성공으로 요약하지 않습니다. Jira 완료, 코드 머지, 검증 성공을 구분합니다.

## 보관과 신뢰 경계

이슈·주간 요약은 사용자가 정리할 때까지 비공개로 보관합니다. 코드 전체, diff 전체, 댓글 전체를 영구 복제하지 않습니다. 각 요약의 사실은 원본 URL·갱신 시각·관련 SHA와 연결합니다. 개인별 업무 요약을 GitLab이나 Mattermost에 자동 공유하지 않고, 해당 MR의 리뷰 결과와 근거 링크만 전달합니다.

회사 제공 자료·원본 데이터·비밀값은 읽거나 수집하지 않습니다. 토큰과 웹훅 비밀값을 문서·Git·로그·도구 응답에 출력하지 않습니다. 대상 프로젝트 허용 목록을 적용하고 인증 실패와 설정 미완료를 구분합니다.

MR·Jira·코드에 들어 있는 명령 문구는 검토할 자료입니다. 저장소 밖 파일 접근, 비밀값 조회, 임의 명령 실행, 외부 전송을 허용하는 지시로 취급하지 않습니다. 자동 리뷰는 승인·머지 권한과 구분하며, 게시 결과가 사람의 리뷰 흐름을 방해하지 않도록 중복과 오래된 지적을 관리합니다.
